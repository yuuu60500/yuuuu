# HMI 趋势面板改造需求（工程师版）

基于版本：HMI v2.33  
需求日期：2026-09-24  
交付目标：用户打开任意周期图表，即可清楚看到当前 H4 趋势的方向、强度、质量和阶段，并知道状态形成的主要原因。

本文是开发需求，不是已实现或已回测通过的说明。以下阈值为首版默认值，需参数化，并通过回放验证后校准；评分不代表胜率。

## 1. 范围与原则

1. 所有趋势指标固定基于 H4，与当前图表周期无关。
2. 仅使用已收盘 H4、当时已确认的摆动点及结构事件。盘中价格不得改变正式评分。
3. 初次加载通过历史回放建立状态；实时更新与历史回放必须使用同一套状态和评分函数。
4. 用新面板替换主面板中的 `str` 和 `CLEAN/MESSY`。旧字段如有必要可保留在诊断日志，但不能再标为趋势强度/质量。
5. 首版评分只用于展示，不以评分阈值自动过滤或修改 CISD/MSS/BPR/PA 确认规则。结构方向算法的修复可能改变依赖 context 的历史结果，需要单独说明并验证。
6. 不增加交易、下单功能。保留多实例隔离。

## 2. 面板要求

固定显示在右上角，位置、字号可配置，避免与现有面板重叠。

正常示例（示例分数不是实测结果）：

```text
H4 趋势    ▲ 多头
趋势强度   强 · 76/100 ↑
趋势质量   良好 · 82/100
当前阶段   延续推进
主要原因   同向推进明显，回撤较浅
数据截至   2026.09.24 12:00 H4 收盘（服务器时间）
```

回撤示例：

```text
H4 趋势    ▲ 多头
趋势强度   中等 · 48/100 ↓
趋势质量   较差 · 31/100
当前阶段   深度回撤
主要原因   回撤偏深，近期突破失败
数据截至   YYYY.MM.DD HH:MM H4 收盘（服务器时间）
```

过渡示例：

```text
H4 趋势    过渡 · 偏空待确认
趋势强度   暂不评级
趋势质量   待确认
当前阶段   反转待确认
主要原因   多头保护低点已破
```

显示约定：

- 多头绿色、空头红色；过渡黄色、区间灰色。
- 强度、质量同时显示文字和数值，可配短色条，不能只靠颜色传达含义。
- 原因最多两条，必须由实际分项或状态生成，不能使用固定赞美性文案。
- RANGE 显示“区间震荡”，强度/质量显示“暂不评级”。
- 数据不足显示“样本不足”；序列尚未同步显示“等待数据”。不得以 0 分、CLEAN 或旧值伪装成当前有效结果。
- 若保留上次有效结果，必须标明“上次有效结果”及其时间。

## 3. 统一数据定义

数组按时间正序，`t` 为当前处理的已收盘 H4 索引。

- `C[t] / H[t] / L[t]`：收盘价、最高价、最低价。
- `D`：已确认多头为 +1，已确认空头为 -1；TRANSITION/RANGE 不计算趋势总分。
- `N=12`：主要观察窗口，需要至少 13 个收盘价。
- `K=3`：近期动量窗口。
- `A=ATR14[t]`：沿用本版本 `SeriesComputeATR` 的 14 期简单平均 TR 算法，避免静默换成另一种 ATR 平滑方式。
- `clamp(x,0,1)`：限制到 0～1。
- 所有评分内部保留小数，最终展示四舍五入到整数；等级依据未四舍五入的分数判断。
- 价格零值比较使用适合品种 tick size 的容差；ATR 无效或必要历史不足时，总分不可用。

面板 H4 的数据游标要与评分和结构状态使用的 H4 游标一致。不要用尚未送入结构引擎的 H4 ATR 配合旧 context。

## 4. 方向：结构识别修复

保留 `BULLISH / BEARISH / TRANSITION / RANGE` 四态，继续采用收盘越过参考价且超过突破余量的规则。

### 4.1 修复旧摆动点重复计 BOS

当前 `SwingLastUnswept → H4DetectBreak → H4ConsumeSwing` 每根仅消费一个摆动点，可能在价格没有继续推进时逐根消费更老的点、增加 BOS 次数。

要求：

- 同一根 H4 收盘穿越多个符合条件的同向旧摆动点，只产生一次结构事件。
- 同次穿越的旧摆动点一并标记已处理，不能在后续 K 线再次形成 BOS。
- 用于事件的主参考点按确定性规则选择：最近已确认、未处理且被有效突破的该方向摆动点。
- 新的 BOS 必须代表新的结构推进，不允许回退到已越过的旧水平补计事件。

### 4.2 受保护结构

- 多头：导致一次有效向上 BOS 的回撤低点，作为该段受保护低点；空头对称。
- 首版可实现的确定性选点：有效向上 BOS 时，选择被突破高点之后、BOS 之前最近形成且在 BOS 时已经确认的摆动低点；向下 BOS 对称。
- 未找到合法的新保护点时，保留原有保护点；若连原保护点也不存在，标记结构样本不足，不可临时使用未来确认点补填。
- 保护点在事件确认时冻结。后续有效 BOS 才可根据合法新回撤点更新；多头保护点不能下移，空头保护点不能上移。
- 多头收盘有效跌破保护低点，进入偏空 TRANSITION；空头对称。
- 反转确认需要 CHOCH 之后形成并确认的新反向结构，再发生有效突破。需同时约束摆动点形成时间和确认时间，不能只检查 confirm_time。
- 过渡失败恢复原趋势，也需有新结构的有效突破，不能通过旧水平补计恢复。
- 过渡最大等待沿用默认 18 根后续 H4；计数超过 18 进入 RANGE。超时判断在事件检测之前或之后必须固定并记录，首版沿用原版“先超时判断”的顺序。

上述保护点选取与反转结构约束是本次改造规则，需用正反方向图例和测试样例交付，不能只保留代码注释。

## 5. 趋势强度：0～100

只在 D=+1 或 -1 时计算。

### 5.1 同向净推进，权重 45%

```text
net = D × (C[t] - C[t-N])
S_move = 100 × clamp(net / (3 × A), 0, 1)
```

首版 3 ATR 为该项满分。反向位移计 0。

### 5.2 方向效率，权重 35%

```text
path = Σ abs(C[i] - C[i-1]), i=t-N+1...t
S_eff = 100 × clamp(max(net,0) / path, 0, 1)
```

`path=0` 且数据有效时，此项为 0。

### 5.3 近期动量，权重 20%

```text
recent = D × (C[t] - C[t-K])
S_mom = 100 × clamp(recent / A, 0, 1)
```

首版最近 3 根同向推进 1 ATR 为该项满分。

### 5.4 合成与等级

```text
Strength = 0.45×S_move + 0.35×S_eff + 0.20×S_mom
```

| 区间 | 等级 |
|---|---|
| [0,35) | 弱 |
| [35,65) | 中等 |
| [65,100] | 强 |

变化箭头比较当前分数与 3 根 H4 前的分数：差值 >=5 为 ↑，<=-5 为 ↓，其余为 →。只有两端属于同一连续趋势段且评分有效才比较，否则显示“新趋势”。5 分为可配置默认值。

新趋势建立后，12 根窗口仍按实际历史计算，不偷偷缩短窗口；因此刚反转时强度可能偏低，这是初版定义的自然结果。

## 6. 趋势质量：0～100

质量衡量突破可靠、回撤健康和价格反复程度，不复用 BOS 累计次数。

### 6.1 突破可靠性，权重 40%

记录结构引擎产生的 BOS 事件：方向、趋势段 ID、发生时间、冻结参考价、后续观察结果。

- 选取最近 12 根 H4 内发生、方向与当前趋势一致且属于当前趋势段的 BOS。
- BOS 后完整观察 3 根已收盘 H4。
- 这 3 根中任意一根收盘回到冻结突破水平的另一侧，视为失败；等于参考水平不算失败。
- 满 3 根且未失败，视为成功。
- 为保持样本年龄一致，只将满 3 根观察期的事件计入评分；未满期的事件标记待确认，不进入分母。

```text
Q_break = 100 × 成功事件数 / 已完成观察事件数
```

没有已完成观察事件时，该项无效，质量总分显示“待确认／样本不足”，不当作满分，也不擅自改权重。

### 6.2 回撤健康度，权重 35%

以最近有效 BOS 对应的受保护点为推进起点，维护从该起点至当前的趋势方向极值。新保护点只在合法 BOS 时更新，极值随已收盘数据推进。

多头：

```text
leg = 本段最高价 - 保护低点
r = (本段最高价 - C[t]) / leg
```

空头：

```text
leg = 保护高点 - 本段最低价
r = (C[t] - 本段最低价) / leg
```

`r` 限制到 0～1；缺少保护点或 leg<=0 时此项无效。

采用连续分段线性评分，避免阈值附近突然大跳：

- r=0 至 1/3：100 分。
- r=1/3 至 2/3：从 100 线性下降至 40。
- r=2/3 至 1：从 40 线性下降至 0。

若保护结构已被有效突破，先切换 TRANSITION，再按过渡状态显示，不继续发布原方向质量分。

### 6.3 K 线重叠程度，权重 25%

对最近 12 根 H4 内相邻的 11 对 K 线计算：

```text
intersection = max(0, min(H[i],H[i-1]) - max(L[i],L[i-1]))
union_span = max(H[i],H[i-1]) - min(L[i],L[i-1])
overlap = intersection / union_span
Q_overlap = 100 × (1 - 所有有效相邻对 overlap 的平均值)
```

`union_span=0` 时按 overlap=1 处理，表示完全没有区间推进。缺失行情不能伪造成零波幅 K 线。

该项只反映重叠，不能单独证明趋势良好，因此仅占 25%。

### 6.4 合成与等级

三个分项均有效时：

```text
Quality = 0.40×Q_break + 0.35×Q_retrace + 0.25×Q_overlap
```

| 区间 | 等级 |
|---|---|
| [0,40) | 较差 |
| [40,70) | 一般 |
| [70,100] | 良好 |

必须支持“强度强、质量差”和“强度中等、质量良好”，两者不能相互覆盖。

## 7. 当前阶段

按以下优先级判断，避免同一根出现两个阶段：

1. 数据未同步/必要历史不足：等待数据/样本不足。
2. TRANSITION：反转待确认，展示待确认方向及保护点破坏原因。
3. RANGE：区间震荡。
4. 已确认趋势，但缺少合法保护点：结构待完善。
5. 已确认趋势、回撤比例 r>2/3：深度回撤。
6. 已确认趋势，当前 K 线刷新此前本段趋势极值，且收盘距离本段极值不超过 0.25 ATR：延续推进。
7. 其他已确认趋势：正常回撤；若 r 接近 0 且未创新极值，显示“高位整理”（多头）或“低位整理”（空头）。首版接近 0 的条件为距极值 <=0.25 ATR。

上述 0.25 ATR 为实现显示所需的初版容差，可配置。仅影线创新高但收盘明显回落时，不应显示延续推进。

## 8. 主要原因生成

最多两条，优先解释风险和分歧：

- 结构被破坏 → “多头保护低点已破”/“空头保护高点已破”。
- r>2/3 → “回撤偏深”。
- 窗口内存在已完成观察的失败 BOS → “近期突破失败”。
- 近期动量分项为 0 且 recent<0 → “近期逆向运行”。
- 方向效率低于 35 → “价格往返明显”。
- 上述负面条件不存在，再按高分分项说明“同向推进明显”“回撤较浅”等。

日志应保留全部分项和计数，便于解释总分，不只输出最终标签。

## 9. 数据、绘图和一致性前置修复

以下问题已在 v2.33 审核中发现，会直接影响新面板可信度，应同步处理：

1. **对象登记去重**：ObjectCreate 返回 true 不代表首次创建；OM_Register 必须按名称唯一登记。更新面板不能不断增加注册数量。
2. **跨周期同步**：CopyRates 数据未准备好与“没有新 K 线”必须区分。不得用过期 H4 推进依赖它的 M5 状态。
3. **历史修正重建**：处理 prev_calculated==0，并检查独立 H4/M5 序列的历史变更。
4. **参数校验**：禁止负数 SwingLeft/Right；ATR/观察窗口/分母和数组索引全部验证。
5. **日志脚本修复**：ReloadTest.ps1 当前先过滤 HMI-BUILD，再寻找 HMI-LIVE，导致实时样本永远为 0。修复后才能用于验收。
6. **统一保留策略**：同一数据和参数下，实时与重建后的有效状态、评分、阶段、可见标记应遵守同一套保留规则。

面板更新必须独立于 M5 信号是否出现；有新 H4 收盘且数据就绪就应更新。历史加载和确认时点不能引入未来数据。

## 11. 验收标准

### 功能与解释

- 任意图表周期打开后，明确显示 H4 方向、强度、质量、阶段和数据时间。
- 每个分数可由日志中的原始分项复算，误差只允许来自显示舍入。
- 没有结构/突破样本时，正确显示待确认，不输出虚假的良好质量。
- 过渡/区间不显示原趋势的有效总分。

### 必测情景

1. 多头连续推进、空头连续推进：对称行情应得到对称评分。
2. 持续横盘、往返震荡：不能因旧 BOS 累计而保持强趋势评分。
3. 一根收盘越过多个旧高/低点，之后价格不动：只产生一次 BOS，后续不补计。
4. 正常回撤、深度回撤、保护结构破坏：阶段按顺序和优先级变化。
5. 突破后 3 根内失败：只有事件观察完成后才进入质量统计；历史回放不可提前知道结果。
6. TRANSITION 成功反转、失败恢复、超时进入 RANGE。
7. 历史不足、ATR=0、平价 K 线、CopyRates 暂未就绪、断线恢复。
8. 修改历史/补洞后重建，以及负数 swing 参数被拒绝。
9. 同一数据快照、同一配置：逐根回放与一次历史重建的每个 H4 时点状态完全一致。
10. 连续刷新、多实例、切换图表周期：对象数量稳定，无面板消失或互相删除。

### 交付物

- 完整修改源码和版本说明。
- MetaEditor 编译结果，目标为 0 error、0 warning。
- 默认参数表和评分说明。
- 覆盖上述情景的测试结果及代表性截图。
- 真实行情实时/重载对比日志，记录终端版本、品种、服务器时区、数据区间和参数。
- 明确区分逻辑正确性验证与阈值效果回放；不能以编译通过替代评分有效性验证。

## 12. 开发顺序

先完成对象/数据一致性和结构事件修复，再实现强度分项、质量分项和阶段，最后接入面板与日志。评分上线初期保持展示用途；是否将分数用于交易信号过滤，应作为后续单独需求。
