Mechanism (both symbols, every differing row traced):
  1. Warm-up suppresses POI touches (ProcessClosedM5Bar returns before Phase 3 while n < 100).
     Price is already inside a POI when warm-up ends, so each build starts its first session on
     its OWN first post-warm-up bar: EURUSD 09.15 12:15 vs 15:45, XAUUSD 09.14 18:45 vs 21:35.
  2. That session ends by TIMEOUT 288 bars later - again 3.5 h / 2 h 50 min apart.
  3. In the build whose session lives longer, blocks / ARMED of that session exist that the other
     build cannot make (its session has already timed out); their cycles then confirm models,
     and a cycle outlives its session until the next ARMED (Rule 15). The other build keeps its
     previous cycle open instead (XAUUSD cycle 602: CISD / MSS 09.16 21:55 in build 2 only).
  4. The differences end at the next ARMED common to both builds: nothing differs afterwards
     (EURUSD 09.16 16:45, XAUUSD 09.17 04:55; three weeks identical after that).
  The 24 h settle of the reload check is shorter than "session lifetime (288 bars) + the cycle
  armed at its end", so these rows fall inside the comparable region.

Not repaint / future leak: each build is causal on identical data; the difference is only where
processing started. Not new in v2.53 (the warm-up gate is the same in v2.48 / v2.52) and not
related to the BOS de-dup (H4 CTX identical in both builds).
Acceptance consequence: a same-version reload is judged on two builds of the SAME window -
two reloads inside one M5 bar (docs/04 v2.53 item 5); automatically moved windows are not used.
